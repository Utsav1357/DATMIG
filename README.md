Three ADRs are written out in full — 0004, 0018 and 0019 — because they carry the correctness argument. The rest follow the same template and should be written as they are implemented, not all at once: an ADR written before the decision has been exercised tends to document an intention rather than a decision.

## Reading order for a new engineer

1. **ADR-0018** — what point in time are we even migrating?
2. **ADR-0004** — how does progress survive a crash without a distributed transaction?
3. **ADR-0019** — why rejects get the same guarantee as data.
4. Architecture §12.6 — the difference between *target atomic chunk commit* and *end-to-end exactly-once*, and the six invariants the stronger claim requires. Read this before using either phrase in code, documentation or conversation.
